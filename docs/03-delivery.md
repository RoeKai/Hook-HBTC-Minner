# 迭代、验收标准与首轮开发任务
版本 0.1 · 2026-09-10

## 迭代闸门
一个迭代交付代码、说明与证据 → 固定 commit 审查 → 运行测试 → 对照需求 → PASS 才进入依赖它的下一迭代。状态为 PASS / FAIL / BLOCKED；缺证据为 BLOCKED，不算通过。文档审查通过不等于链上实现通过。

| 轮次 | 交付 | 验收闸门 |
|---|---|---|
| R0 产品与接入研究 | 本文档组、来源登记、目标接入清单、能力试验设计 | G0：目标身份、ABI、源码与资产归属核验；目前 BLOCKED |
| R1 只读与模拟基础 | 项目结构、配置验证、整数金额、协议适配接口、模拟状态与仪表盘；明确演示标签 | G1：未知配置阻断交易、只读失败不显示假零、数学边界和状态机测试通过 |
| R2 钱包手动链路 | 正确链连接、单次买入、work 对账、领取、交易跟踪 | G2：固定 fork/测试环境买入领取与错误路径通过，无用户私钥入口 |
| R3 有限授权自动化 | 选定智能账户/策略合约、keeper、预算、幂等、暂停/撤销/直接退出 | G3：合约性质测试、恶意调用拒绝、并发/崩溃恢复/关闭页面测试通过 |
| R4 点数与财务 | 支付、账本、扣点、退款、费用/奖励对账、导出 | G4：重复事件/失败/重组/退款竞态不多收多退，商业价格定稿 |
| R5 上线准备 | 完整回归、安全审查、压测、监控、运行手册、发布回退方案 | G5：P0/P1 清零，合约审计问题关闭；生产参数核实；可执行退出路径 |
| R6 小范围运行 | 经用户明确选定真实资金预算的试运行、观察与扩量 | G6：实际账单与链上证据对账，故障演练完成后再扩量 |

R1 的不依赖目标链部分可做设计/离线原型；不得以此绕过 G0 开始真实链上开发。本轮只提交 R0 文档草案。新项目尚未指定链与合约，R0 不能验收为已完成。

## 缺陷优先级与通过条件
P0：资金/权限越界、错误归属、重复支出、私钥暴露、账务不守恒。P1：核心逻辑、稳定执行或撤销失败、关键数据误导。P2：不改变资金结果的体验问题。P3：非必要优化。
PASS 需本轮要求全部有证据；P0/P1 为0；P2若影响本轮验收也必须修复。任何例外单列影响、负责人和处理时间，不把跳过测试写为通过。

## GitHub 交付约定
仓库：https://github.com/RoeKai/Hook-HBTC-Minner
初始基线：main@0bc5aacec5cdf9d493a39e36ff8355acd67407e9；仅 README.md 与 .gitignore。main 当前未启用分支保护，本文流程不会自动建立平台强制保护。

分支建议 docs/r0-product-baseline、feat/r1-readonly、feat/r2-wallet、feat/r3-automation、feat/r4-billing、release/r5。
每轮一个可审查 PR，基于上一轮通过的提交；不把若干未验收轮次混合提交。PR 说明包括需求 ID、实现行为、验证命令及真实输出摘要、截图/运行证据、数据库变化、兼容性、已知限制、回退方式。
提交信息采用 docs:/feat:/fix:/test:；不得提交钱包私钥、助记词、RPC 密钥或生产凭据。部署配置样例只用占位符。锁定依赖；CI 最小读权限；外部 PR 不接触生产密钥。

验收报告路径 docs/acceptance/Rn-<shortSHA>.md：
- 固定 base/head SHA、PR URL、环境与目标区块/合约哈希。
- 逐条需求：实现位置、测试用例、实际结果、证据路径。
- 全量变更审查，不能只读 PR 摘要；检查 CI 是否确实对应 head。
- PASS/FAIL/BLOCKED，剩余缺陷与下一步。
- 新提交后旧验收失效，对变更及受影响回归复验。
自己实现并复核要标注自审；不冒充独立安全审计。重大资产权限合约上线前另做独立安全审查。

发布回退：暂停新增 keeper 任务→确认在途→切回已验证前端/服务版本→重放索引/账本核对。不可逆合约部署不能靠“git revert”恢复；用户撤销与退出路径要单独演练。实际主网签名与资金操作由用户控制钱包。

## 给下一轮 Codex 的可执行任务单：R0 接入验证
目标：补齐 HBTC-Copy 的身份和自动挖矿能力证据，做出可执行/半自动/不可行结论。
输入：本组文档、目标官网/链/合约与 ABI/源码、可读 RPC；缺失不得猜地址。
步骤：
1. 阅读仓库约束和上述产品基线；固定 base SHA，建立专用分支。
2. 生成 docs/integration/target-manifest.json，未验证字段留 null、enabled=false。
3. 在固定链区块读取并保存 code hash、池参数、genesis、fee、reward；核验代理和权限。
4. 解码公开交易，验证买入资产、work、claim 的归属；列明第三方工具与目标机制差异。
5. 在本地 fork 仅使用测试账户/虚拟余额，测试普通钱包与合约执行器路径，给出失败原因。
6. 提交能力 ADR：选哪种账户/授权方案，哪些约束由链上强制，Gas由谁付，keeper能做什么，用户如何独立退出。
交付：证据、manifest、ADR、可重现测试脚本和结果、PR；禁止真实资金交易、未经核实的生产地址。
DoD：AC02/AC04/AC22 中属于接入的部分有实际结果；B01/B02/B03得到可核实解答。未通过留 BLOCKED，不启动 R2/R3。
